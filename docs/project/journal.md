**Session 49 — Debug UX app + refonte filtres Catalogue (branche `refacto/splash-offline-nominal`, mergée `main`)** : détour hors fil Oracle pour fiabiliser l'app côté offline/catalogue. Livré (3 commits, fast-forward sur `main` + push origin) :
- **Splash** : suppression de la page-barrage « astrobrain injoignable » — Pi injoignable = boot **nominal** (Oracle hors ligne), on entre en offline silencieusement ; machinerie d'échec morte retirée (state/screen/cubit).
- **Almanach** : la synchro ne partait pas au lancement — cause racine **environnementale** (repo GitHub privé → assets de la release `almanac-latest` en 404 pour un client anonyme), résolue en passant le repo **public** (scan sécurité préalable : aucun secret tracké, `secrets.h` bien gitignoré). Zéro changement code.
- **Catalogue** : retrait du pré-filtre Messier (chip + chaîne event/bloc/state/repo/provider) ; le champ **donnée** `messier` conservé (badge + recherche texte).
- **Catalogue** : chips `MAG ≤ 3/2` → **RangeSlider** magnitude (bornes −5→+12, pas de 1, requête au relâchement). **Option B** : les DSO sans magnitude cataloguée restent toujours visibles ; seuls les objets notés sont bornés à [min, max] (fixed + ephemeris providers).
- Validé sur device (Moto g54, APK release, Pi éteint). Suites : **app 261** + `flutter analyze` clean.
- Reste : observabilité de `almanacSync.sync()` (résultat encore silencieusement ignoré) → backlog.

**Session 50 — Déploiement Pi + 4 correctifs d'observabilité/correctness (`main`, 2 commits)** : mise à jour du Pi avec la base de code S43→S49 (133 commits de retard), puis correction de ce que le déploiement a révélé. Pas de monture branchée (les erreurs de connexion driver sont nominales).
- **Déploiement** : Pi `fa42e52` → `b86c755`, migrations `_004`+`_005` appliquées (`schema_version` 3 → 5), `catalog_objects` et `mount_limits` confirmées droppées. **`reference.sqlite` téléchargée au boot (13,8 Mo)** — 1ʳᵉ validation end-to-end de la chaîne Oracle SP2 sur le vrai Pi (`/reference/status` `ready: true`). `state.db` sauvegardée avant chaque pull.
- **GPS no-fix traité comme une erreur (correctness, pas juste du bruit)** : `gpsd-py3` lève `UserWarning('GPS not active')` dès que le démon rapporte `mode < 1` — état **nominal** sans fix. Le `except Exception` de `GpsdAdapter._loop` sautait tout le corps de boucle : à la **perte** du fix, l'état publié restait figé sur le dernier fix et `latest_fix()` continuait de servir une **position périmée** à l'orchestrateur et au bridge d'alignement (risque d'aligner/GoTo sur une position morte). Effet visible par ailleurs : **4121 lignes de journal en 2 min 30** (une stacktrace par poll, 2/s, sur la carte SD). Le no-fix suit désormais le chemin de publication normal ; logs **par transition** d'état, erreurs réelles une fois par épisode (ré-armées au rétablissement). Boucle mise sous tests (elle n'en avait aucun).
- **Root logger jamais configuré** : découvert en vérifiant le correctif suivant sur le Pi — uvicorn ne configure que ses propres loggers, le root restait à `WARNING`, donc **tous** les `logger.info` du package étaient jetés en prod (seules les stacktraces WARNING passaient — ce qui explique qu'on n'ait jamais vu que le bruit). `configure_logging()` dans `main.py`, niveau réglable par `ASTRO_BRAIN_LOG_LEVEL`.
- **Sync `reference.sqlite` muette au boot** : succès non logués, et `create_task` nu perdant toute exception hors du set géré (`HTTPError`/`KeyError`/`ValueError`). INFO sur les issues nominales + wrapper `_boot_reference_sync` pour que l'inattendu (disque plein, cache illisible) atteigne journald.
- **Migration `_006`** : purge les lignes `calibration_sensor` des 2× ADXL345 retirés le 2026-07-17, jamais relues (`SENSOR_IDS` = `{lis3mdl}`) et encore présentes sur le Pi. Vérifié après redéploiement : `schema_version` 6, table vide.
- **Ops** : symlink `/usr/local/bin/uv` (le PATH d'un `ssh pi '<cmd>'` non interactif ignore `~/.local/bin`, et l'early-return de `~/.bashrc` empêche tout export d'agir) + procédure de sauvegarde `state.db` documentées dans [`deployment.md`](../technical/deployment.md).
- **Vérifié sur le Pi après redéploiement** : **11 lignes de journal en 60 s** (contre 4121 en 2 min 30), zéro `GPS not active`, et les lignes utiles enfin visibles (`reference: déjà à jour (schema v2)`, `gps state: - -> no_fix (sats=0)`, connexion INDI). Suites : **backend 317** + ruff clean.
- **Aucune calibration compass persistée** sur le Pi (`calibration_sensor` vide) : la calibration LIS3MDL n'a jamais été refaite depuis le passage en heading non tilt-compensé (S42). À faire lors d'une session terrain.
- **Deux points de finition traités dans la même session** (3ᵉ commit) : `httpx`/`httpcore` réduits à `WARNING` sauf en `DEBUG` (ils loguaient l'URL signée complète de la release Oracle, ~700 caractères par requête) + confirmation du niveau effectif au démarrage ; et le **test flaky pré-existant** `test_round_trip_start_finalize_status` corrigé — le `await asyncio.sleep(0.7)` fixe qui coursait l'accumulation de 500 échantillons est remplacé par une attente du **flux public de progression** bornée par `asyncio.timeout`. Au passage, le premier jet de `configure_logging()` n'était pas idempotent (passer à `DEBUG` après un appel en `INFO` laissait `httpx` bloqué à `WARNING`) : la fonction est désormais déclarative. Suites : **backend 319** sur 3 exécutions complètes consécutives, ruff clean.
