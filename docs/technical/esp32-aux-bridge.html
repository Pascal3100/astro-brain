Pont ESP32 WiFi ↔ bus AUX Firmware esp32-aux-bridge — pont transparent TCP:2000 ↔ UART single-wire · pivot dongle CH340

Rôle

Après l'échec du couplage dongle CH340 ↔ bus (S28 : le RX du CH340 perturbe le bus, non découplable passivement), pivot vers un ESP32 qui se pose sur le bus AUX et l'expose en TCP/IP. Le driver indi_celestron_aux a un mode « Celestron WiFi » (= TCP, IP 1.2.3.4 par défaut, port 2000) : il parle le protocole AUX binaire à travers la socket. Le firmware ne fait que transporter les octets dans les deux sens — l'écho single-wire est filtré côté driver. L'ESP32 lit le bus avec un vrai GPIO haute-Z, ce qui supprime par construction le défaut du RX CH340.

Jalons A+B — VERTS (2026-06-13) : LA MONTURE BOUGE.
A — flash → boot → WiFi → socket TCP : AP=AstroBrain-AUX · 2,4 GHz ch1 · IP 192.168.4.1 · TCP 2000 → OPEN
B — étage BC547 piloté par GPIO17, raquette débranchée → rejeu des octets de slew capturés (S28) via TCP → l'AZM tourne dans les deux sens sur commande. Blocage matériel S26→S28 levé. (Slew ~0,5 s/commande en rejeu brut ; le slew continu via le turnaround half-duplex est géré par le vrai driver → jalon C.)

Firmware (sketch Arduino / ESP32)

// esp32-aux-bridge — pont transparent WiFi-AP <-> UART pour bus Celestron AUX
// Jalon A : smoke test (WiFi + TCP:2000). Le bus n'est PAS encore câblé.
//
// Le driver indi_celestron_aux parle le protocole AUX binaire à travers la
// socket TCP ; ce pont ne fait que transporter les octets dans les deux sens
// (l'écho single-wire est filtré côté driver).

#include <WiFi.h>

// ---- Bus AUX (interface single-wire câblée sur ces pins au jalon B) ----
constexpr int      AUX_RX_PIN = 16;   // lit DATA (via R série de protection 3,3V)
constexpr int      AUX_TX_PIN = 17;   // attaque DATA (via étage BC547 open-collector)
constexpr uint32_t AUX_BAUD   = 19200;

// ---- Point d'accès WiFi (jalon A : on s'y connecte depuis ce PC) ----
const char*    AP_SSID  = "AstroBrain-AUX";
const char*    AP_PASS  = "astrobrain";   // WPA2 : 8 caractères minimum
constexpr uint16_t TCP_PORT = 2000;       // port attendu par le mode "Celestron WiFi" du driver

WiFiServer server(TCP_PORT);
WiFiClient client;

void setup() {
  Serial.begin(115200);
  delay(200);

  // Bus AUX : 19200 8N2 (format natif du bus Celestron)
  Serial2.begin(AUX_BAUD, SERIAL_8N2, AUX_RX_PIN, AUX_TX_PIN);

  WiFi.mode(WIFI_AP);
  WiFi.softAP(AP_SSID, AP_PASS);
  IPAddress ip = WiFi.softAPIP();   // 192.168.4.1 par defaut
  Serial.printf("[AUX-bridge] AP=%s  ip=%s  tcp=%u  baud=%lu 8N2\n",
                AP_SSID, ip.toString().c_str(), TCP_PORT, (unsigned long)AUX_BAUD);

  server.begin();
}

void loop() {
  // Accepte une connexion (un seul client a la fois suffit pour le driver)
  if (!client || !client.connected()) {
    client = server.available();
  }

  // TCP -> bus AUX
  while (client && client.available()) {
    Serial2.write((uint8_t)client.read());
  }

  // bus AUX -> TCP
  while (Serial2.available()) {
    uint8_t b = (uint8_t)Serial2.read();
    if (client && client.connected()) {
      client.write(b);
    }
  }
}

Build & flash (workstation Linux)

# toolchain (binaire officiel, pas de curl|sh)
curl -fsSL -o /tmp/arduino-cli.tar.gz \
  https://downloads.arduino.cc/arduino-cli/arduino-cli_latest_Linux_64bit.tar.gz
tar -xzf /tmp/arduino-cli.tar.gz -C ~/.local/bin arduino-cli

# core ESP32 (3.3.10)
arduino-cli config init
arduino-cli config add board_manager.additional_urls \
  https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32

# flash (carte = ESP32 DevKit, puce CP2102 → /dev/ttyUSB0)
arduino-cli compile --upload -p /dev/ttyUSB0 \
  --fqbn esp32:esp32:esp32 /tmp/esp32-aux-bridge

Câblage jalon B — réutilise l'étage BC547 validé

ESP32 GPIO17 (TX) ──[Rb1]── Q1…Q2 (open-collector) ──┐
                                                     ├── DATA (RJ-12 broche 4)
ESP32 GPIO16 (RX) ──[R série ~3,3k]──────────────────┘   ← protège le GPIO 3,3V du ~4,4V bus

ESP32 GND            ──────────────── RJ-12 broche 5 (GND)
+5V de l'étage BC547 ──────────────── pin 5V / VIN de l'ESP32 (alim USB)
RJ-12 broche 3 (+12V) ────────────── rien  ⚠ NE JAMAIS connecter

L'étage open-collector 2× BC547 (validé électriquement à 0,05 V de niveau bas, S28) est conservé tel quel — il est juste désormais piloté par le GPIO17 de l'ESP32 (3,3 V suffit à saturer Q1) au lieu du TX du dongle. Schéma interne de l'étage : aux-single-wire-cablage.html.

Topologie réseau

L'AP est en 2,4 GHz canal 1 — invisible depuis un PC resté associé en 5 GHz (il a fallu libérer la radio pour le smoke A). Conséquence pour le déploiement : l'ESP32 passera en mode station et rejoindra le réseau / hotspot du Pi (le Pi garde sa liaison avec le téléphone et atteint l'ESP32 par IP). Pour le smoke jalon C, on peut faire l'inverse temporairement (Pi qui rejoint l'AP de l'ESP32).

GPIO 3,3 V sur bus 5 V : le bus idle vers ~4,4 V (pull-up interne monture) > 3,6 V max du GPIO ESP32 → le R série sur RX est obligatoire (la diode de clamp interne + le R limitent le courant à <1 mA).
Orientation RJ-12 : repérer le +12 V (broche 3) au multimètre, monture allumée, avant tout branchement. Un +12 V sur l'ESP32 le grille.
